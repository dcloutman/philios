### Contradictions Found
- **Exit status.** The plan expects `-1` at the shell. Plan 0001 D20 makes that status 255. Resolved by D1.
- **`not()`.** The plan's "Filtering `null` Types" section uses `not()`, but the plan no longer defines it. Resolved by D2. The section must be removed or rewritten using D9 and D10.
- **Unary minus.** Q4 ("B": add unary minus as an operator) and Q5 ("A": unary minus on any expression, with a runtime type error for a value that is not an `Integer`) were replaced by Q7 to Q9. Resolved by D4.
- **Range of negative literals.** Q6 ("A": `-9223372036854775808` is a lexical error) was answered when `-` was an operator. Q11 replaced it after `-<digits>` became a single literal. Resolved by D6.
- **Plan 0001 D22.** Plan 0001 deferred negative literals and documented that `INT64_MIN` could not be written. D4 to D7 replace that limitation.
- **Plan 0001 D14 (exact typing).** D9 replaces exact type matching with subtype acceptance for `Object` and nullable types.
- **Plan 0001 section 3.3 reserved words.** That list does not include `not`, `goto`, `isa`, `echo`, or `typeof`. D2 and D8 require changes to it.
- **Output to stdout.** Plan 0001 section 4 says "Nothing is ever written to stdout." That rule only reflected plan 0001's scope, which left out `echo` on purpose. Resolved by D13: plan 0002 replaces the rule.
- **Unresolved: the `Function` base class.** The plan says that the `Function` base class "will be implemented in a later plan". Plan 0001 D16 already implemented `Function` as an `Object` subclass. The plan text needs to be corrected. This was not raised in the session.

### Deferred / Out of Scope
- An `Object` method named `__toString()` that lets `Integer` and `Float` values convert to `String`: a future plan (D16). Until then, `echo` accepts only `String` values.
- Unary minus, binary `-`, `+`, `*`, and all other arithmetic: a future arithmetic plan (D4).
- `not()` and filtering `null` from data structures: no target plan (D2).
- `goto` and `isa`: reserved with no meaning yet. No target plan (D2).
- Interfaces, including `ImmutableObjectInterface`: part of the future vision. No target plan (D19).
- The `--` operator, a future C-style decrement operator: a future plan (D22).
- Declaring `ImmutableObject` and `NullObject` as types: a later plan (D11).
- `Array` and other data structures named in the plan's examples: plan 0010 and later.

### Answered From the Repository
- **`-` today:** `-` is an unexpected-character lexical error outside strings and comments. Source: `plans/0001.md` sections 3.3 and 4.
- **Exit status:** `main`'s result is taken modulo 256, so -1 maps to 255. Source: `plans/0001.md` section 3.8, D20.
- **Reserved type names:** `Object`, `ImmutableObject`, and `NullObject` are already reserved words. Source: `plans/0001.md` section 3.3.
- **Existing object model:** `Object`, `ImmutableObject`, `Integer`, `String`, `NullObject`, and `Function` already exist, and `null` is one `NullObject` per execution context. Source: `plans/0001.md` sections 3.6 and 3.9; `src/runtime/object_model/`.
- **Integer literal range today:** literals range from 0 to 9223372036854775807, and leading zeros are rejected. Source: `plans/0001.md` section 3.3, D28d.

### Recommended Changes for the plan-composer
- Change the acceptance text of "Negative Integer Support" so that `return -1` must exit with status 255 (D1).
- Remove the "Filtering `null` Types" section and the `not()` references. Describe `null` handling with `?Type` instead (D2, D9, D10).
- Add `not`, `goto`, and `isa` to the reserved words with no meaning yet (D2).
- Define `typeof(expr)`: it accepts any expression, evaluates it, and returns a `String` holding a script-level type name (D3, D12). Add test cases for `null`, `Function`, and a call result.
- Define `echo` and `typeof` as callable only. A bare use is an error before execution, and the plan must state which error class applies (D8).
- Specify the negative literal: the contextual lexing rule (D5), the range down to `-9223372036854775808` (D6), and rejection of every `-0...` form (D7). Add boundary tests for `-9223372036854775808`, `-9223372036854775809`, `9223372036854775808`, `-0`, `-007`, `a-1` in a call argument, and `f(1)-1`.
- Do not add unary minus or any arithmetic operator (D4).
- State that `echo` writes to standard output and that this replaces plan 0001's rule that nothing is written to stdout. Diagnostics stay on standard error (D13).
- Define `echo` with the signature `echo(String str): null`. Add tests for a non-`String` argument, a wrong argument count, and `typeof(echo("x"))`, which writes `x` and returns the `String` `"null"` (D12, D14).
- Specify the `echo` checks: the parser reports the wrong number of arguments and invalid literal arguments as `syntax` errors. Arguments of other types are checked at runtime and fail with a `runtime` error. Give the error location for each case and add one test for each (D15, D16, D17).
- Specify the type grammar: the declarable types and their nullable forms (D10, D11). Specify subtype acceptance and the `null` rule (D9). Update the plan 0001 rules that D9 replaces.
- Correct the statement that the `Function` base class is future work, because plan 0001 D16 implemented `Function`.
- Report a failure to write output as an error, with an error status returned to the shell (D18).
- Remove the statement that `ImmutableObject` implements `ImmutableObjectInterface` (D19).
- Add `echo` and `typeof` to the reserved words (D20).
- Allow a negative literal after `return`, so `return -1` exits with status 255 (D1, D21).
- Make `- 1` and `--1` `syntax` errors, and keep the lexer compatible with a future `--` operator and future subtraction (D22).
- Keep the plan 0001 rule that `main` returns `Integer` (D23).
- Specify that `echo` writes the string's bytes exactly, with no added line break, and add a test for a string with no trailing line break (D24).
