# Variable Declarations, Assignment, and Common Operators

## 0. Boolean Type
A `Boolean` type is either `true` or `false`, both of which are reserved keywords and global symbols. A `Boolean` variable is subclassed from `Object`.

## 1. Variable Names
- A name contains only ASCII letters (`A-Z`, `a-z`), ASCII digits (`0-9`), and underscores (`_`).
- A name may start with zero or more underscores. The first character after any leading underscores must be a letter.
- After that first letter, letters, digits, and underscores may appear in any order.
- Equivalent pattern: `_*[A-Za-z][A-Za-z0-9_]*`.
- Names are case-sensitive: `foo`, `Foo`, and `FOO` are three different names.
- Reserved words cannot be used as names.

| Name | Valid? | Reason |
|---|---|---|
| `count` | Yes | |
| `_count`, `__count` | Yes | Leading underscores followed by a letter |
| `count_2`, `a1b2` | Yes | Digits and underscores after the first letter |
| `_`, `__` | No | No letter |
| `1count` | No | Starts with a digit |
| `_1count` | No | A digit comes before the first letter |

## 2. Variable Declarations
- Syntax: `let <name>: <Type>` or `let <name>: <Type> = <expression>`.
- The type annotation is required.
- A `?` before the type makes it nullable: `let name: ?String` accepts a `String` or `null`.
- A variable with a non-nullable type must be initialized in its declaration. `let name: String` without `= <expression>` is an error.
- A variable with a nullable type may omit the initializer.
- A name can only be declared once in a scope. Should it be redeclared in the same scope, thow an error.
- Using a variable before its declaration produces an error.

```
let count: Integer = 0      // valid
let name: ?String           // valid: nullable, no initializer
let title: ?String = null   // valid
let label: String           // error: non-nullable type without an initializer
```

## 3. Assignment
- Syntax: `<name> = <expression>`.
- Variables declared with `let` are mutable and may be reassigned any number of times.
- The type of the assigned value must match the variable's declared type. A nullable variable also accepts `null`. A mismatch is an error.

**Assignment is a statment:** `a = b` is a statement only. It does not produce a value.

## 4. Constants
- Syntax: `const <name>: <Type> = <expression>`.
- Naming, type annotation, and nullability rules are the same as for `let`.
- A constant cannot be reassigned. Any assignment to a constant after its declaration is an error.
- Like a variables, the scope of a constants are bound to the block in which they are declared. They may be declared at a module level.

## 5. Symbols
- Syntax: `symbol <name>`
- A symbol is a programmatic token that references a fixed point in memory. It has no value and assigning a value to a symbol results in a error. A symbol may belong to a class. It is useful in cases when one might create a constant with an arbitrary value.
- Naming rules are the same as for a variable and a constant.
- Symbols are scoped to the block in which they are declared. They may be declared at a module level.

## 6. Logical Negation Operator `!`
- `!` is a prefix operator. `!true` is `false`, and `!false` is `true`.
- The operand must be a boolean. Applying `!` to any other type is an error.

## 7. Equality Operator `==`
- `a == b` is `true` only if both operands have the same type **and** equal values.
- If the types differ, the result is `false`; it is not an error. Example: `1 == "1"` is `false`.
- If the types match but the values differ, the result is `false`.

## 8. Inequality Operator `!=`
- `a != b` is always the opposite of `a == b`: it is `false` when `a == b` is `true`, and `true` otherwise.

## 9. Arithmetic Operators
These operators are recognized. Their operand types, result types, and edge-case behavior are not yet specified (see Open Questions).

| Operator | Name |
|---|---|
| `+` | Addition |
| `-` | Subtraction |
| `*` | Multiplication |
| `/` | Division |
| `%` | Modulus |
| `**` | Exponentiation |

**Arithmetic semantics:** Arithmetic operations work on `Integer` and `Float`. If a `Float` is mixed with an integer in an expression, integers are automatically cast to `Float`, excepting modulus. Arithmetic expressions with only `Integer` types result in an `Integer`.

**Precedence and associativity:** Arithmetic operators follow standard mathematical rules. The `!` operator executes before the equality operator. Eventually, we expect our operators to be implemented according to this table. *Do not implement an operator unless explicitly instructed to do so.*

| Precedence | Operator | Description | Associativity |
| :--- | :--- | :--- | :--- |
| **1 (Highest)** | `new` | Object instantiation | Non-associative |
| **2** | `**` | Exponentiation | Right |
| **3** | `++`, `--` | Increment/decrement | Non-associative |
| **4** | `isa` | Type check | Non-associative |
| **5** | `!` | Logical NOT | Non-associative |
| **6** | `*`, `/`, `%` | Multiplication, division, modulo | Left |
| **7** | `+`, `-`, `.` | Addition, subtraction, string concatenation | Left |
| **8** | `<`, `<=`, `>`, `>=` | Less than, greater than comparisons | Non-associative |
| **9** | `==`, `!=` | Equality, and non-equality | Non-associative |
| **10** | `&&` | Logical AND | Left |
| **11** | `\|\|` | Logical OR | Left |
| **12** | `if <epression> then <value> else <value>` | Ternary conditional | Non-associative  |
| **13** | `=` | Assignment operator | Right |


## Additional Information
These must be answered before implementation. Implementers must not choose answers on their own.

**New reserved words:** `let`, `const`, `true`, `class` and `false` are to be added to the reserved-word list.

**Old Plans Superceded** Nothing in a previously written plan shall supercede this plan. Things change between plans and old plans loose value quickly. Use the official documentation in `docs` and the code in `src` as a current source of truth. This plan may change facts discerned from those sources. Ask if uncertain.

**Identifier Rule** Section 1 applies to all identifiers. It is intentionally more strict than previously recorded.

**Error Detection:** Missing initializer, type mismatches, assignment to a constant, and `!` on a non-boolean are all detectable when a file is parsed. Look for them then.

**Uninitialized nullable variables:** `let name: ?String` starts as `null` when unassigned. `const name: ?String` is `null` until is assigned a `String` value, after which its value cannot be changed. This is true of all nullable type constants. 

**Value equality:** Class instances count as "equal values" for non-immutable types. `null == null` is `true` because `null` always points to the same place in memory. A subtype cannot be equal to a supertype.

**Compound assignment:** Compound assignments are out of scope.

**Module Scope:** Constants, symbols, function, and class declarations can all exist at a module level. (Classes will be implemented later.)
